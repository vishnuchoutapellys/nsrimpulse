# Authentication

Student login returns a 15-minute JWT with the `STUDENT` role and immutable `studentUid` claim. Portal, payment-history, and student-payment routes require that bearer token and compare its identity to the requested or submitted student ID. College Admin login returns an 8-hour `COLLEGE_ADMIN` JWT; each admin operation reloads the active user and assigned college from PostgreSQL before reading or mutating student data. College Admins can access all branches and courses within that college, but cannot access another college's records.

Students cannot self-register. An authorized College Admin creates the student record with a required email and mobile number. The backend generates the Student ID and a cryptographically shuffled six-character temporary password, stores only its bcrypt hash, and sends the credentials through configured email. A temporary-password login returns a short-lived password-change token rather than portal access; the student must set a password containing uppercase, lowercase, number, and special characters before receiving a student JWT.

Password recovery creates a ten-minute challenge and sends separate six-digit OTPs through SMTP and the configured SMS webhook. Both codes must match within five attempts. Successful verification issues a hashed, one-time reset token that expires after ten minutes. Completing a reset consumes all outstanding challenges for that account, clears login lockouts, and invalidates the reset token. Login is temporarily locked for fifteen minutes after five failed attempts. Public recovery responses do not disclose whether a Student ID exists.

For email, Resend is used when `RESEND_API_KEY` is configured; otherwise, the application falls back to SMTP using `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, and `SMTP_PASSWORD`. Both providers require `EMAIL_FROM`. In Resend, verify your sending domain and use a sender address on that domain, create an API key, then add `RESEND_API_KEY` and `EMAIL_FROM` to the backend environment (the repository-root `.env` for local development). Keep the API key server-side and never add it to a `VITE_*` variable or commit it. Restart the backend after changing environment variables. Email delivery also powers student credentials and password-recovery messages. SMS recovery is separate and still requires `SMS_WEBHOOK_URL` and optionally `SMS_WEBHOOK_TOKEN`; the webhook must accept an authenticated JSON request shaped as `{ "to": "...", "message": "..." }`.

The current application does not yet implement refresh-token rotation/revocation, logout revocation, or access-token renewal; users must sign in again when the student token expires.
