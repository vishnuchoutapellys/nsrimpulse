# API contract

All endpoints use `/api/v1` and return `{ success, data, message }` on success or `{ success: false, error: { code, message, details } }` on failure. Request validation uses Zod; unexpected server errors are logged server-side and returned as a generic `INTERNAL_ERROR`.

| Method | Path | Access |
| --- | --- | --- |
| GET | `/health` | Public |
| GET | `/api/v1/public/overview` | Public |
| POST | `/api/v1/students/validate` | Public validation only; does not persist |
| POST | `/api/v1/auth/login` | Public; returns a password-change token for temporary credentials or a 15-minute student JWT |
| POST | `/api/v1/auth/change-temporary-password` | Public with a valid short-lived password-change token |
| POST | `/api/v1/auth/forgot-password` | Public; sends separate email and mobile OTPs without disclosing account existence |
| POST | `/api/v1/auth/forgot-password/verify` | Public; verifies both OTPs and returns a one-time reset token |
| POST | `/api/v1/auth/forgot-password/reset` | Public with a valid one-time reset token |
| GET | `/api/v1/students/:studentUid/portal` | Student JWT for the same `studentUid` |
| GET | `/api/v1/students/:studentUid/payments` | Student JWT for the same `studentUid` |
| POST | `/api/v1/payments/student` | Student JWT; submitted `studentUid` must match token |
| POST | `/api/v1/admin/auth/login` | Public College Admin login |
| GET | `/api/v1/admin/context` | College Admin JWT |
| GET | `/api/v1/admin/students/search` | College Admin JWT; searches students in the admin's college across all courses and branches |
| GET | `/api/v1/admin/students/:studentUid` | College Admin JWT; student must belong to the admin's college |
| POST | `/api/v1/admin/students` | College Admin JWT; student is created in the admin's assigned college; the backend assigns its default campus branch and generates/emails credentials |
| GET | `/api/v1/admin/reports/fee-collections` | College Admin JWT; fee allocations limited to the admin's college |
| POST | `/api/v1/admin/notifications/send-due-reminders` | College Admin JWT; counts upcoming dues only for the admin's college |
| POST | `/api/v1/admin/students/:studentUid/offline-payments` | College Admin JWT; student must belong to the admin's college |
| POST | `/api/v1/admin/students/:studentUid/certificates/issue` | College Admin JWT; student must belong to the admin's college; audits TC or Bonafide/Conduct generation and returns current outstanding fees |
| GET | `/api/v1/super-admin/context` | Super Admin JWT; includes colleges, locations, and College Admin account statuses |
| GET | `/api/v1/super-admin/students/search` | Super Admin JWT; cross-college student directory with optional college/branch filters |
| GET | `/api/v1/super-admin/reports/fees` | Super Admin JWT; cross-college fee report with optional college/branch/year filters |
| POST | `/api/v1/super-admin/student-discounts` | Super Admin JWT; assigns a discount to a current student fee assignment |
| POST | `/api/v1/super-admin/colleges` | Super Admin JWT; creates a college in a configured location |
| DELETE | `/api/v1/super-admin/colleges/:id` | Super Admin JWT; refuses colleges with students or assigned College Admins |
| POST | `/api/v1/super-admin/admins` | Super Admin JWT; creates a College Admin with access to the selected college |
| PUT | `/api/v1/super-admin/admins/:id` | Super Admin JWT; updates College Admin ID, email, and account status |

Student and College Admin credentials use `Authorization: Bearer <accessToken>`. Student IDs are authorization-bound on every student data/payment route; changing the URL or request body to another ID is denied. The student payment endpoint is a development simulation, not a provider-verified payment flow. Refresh-token rotation and payment provider order/verification/webhook routes are not implemented yet.

There is no public student-registration endpoint. Admin student creation requires a valid email and mobile number but does not accept a Student ID or password; both are generated by the backend. Notification provider settings are listed in `.env.example`.

College Admin account status is `ACTIVE`, `HOLD`, or `BLOCKED`. Only active accounts can log in or continue using an existing session; hold and blocked accounts receive a status-specific message and must contact the Super Admin. Super Admin provisioning assigns the College Admin to one college; the admin can create, search, view, and report on students across that college. All courses remain available for selection. The backend assigns a `Main Campus` record for student storage when needed; admins do not manually configure branches. College Admins cannot access another college's data; only the Super Admin API can access cross-college student data. Legacy unauthenticated `/api/v1/college-admin/*` endpoints are disabled.

Certificate issuance accepts `{ "certificateType": "TRANSFER" | "BONAFIDE_CONDUCT", "fields": { ... } }`. The admin UI loads a scoped student record first, pre-fills available profile fields, and warns about unpaid fees. Outstanding fees do not block certificate generation; the issue endpoint recalculates the balance and writes the document fields and current due amount to the audit log.
